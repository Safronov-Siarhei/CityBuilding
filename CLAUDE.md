# CityBuilding — instructions for Claude

- Reply to the user in Russian.
- **Don't read the whole project.** Start from `Design/features/README.md` (the feature index), then
  read only the cards the task touches, then only the code files those cards list.
- **After every finished task, update the touched feature card(s)** — status line, rules the user
  decided, files, traps, open items — and add a card + index row for a new feature. Cards are the
  project's memory; a stale card is worse than none.
- Numbers and text never go into C#: see `Design/features/balance-and-localization.md`.
- The whole game is generated by `Assets/_Project/Scripts/Editor/SetupProject.cs` in Unity batchmode:
  see `Design/features/build-and-test.md` before running Unity. Run Unity only through
  `Tools/research/run.ps1` and read its short report; open `RunLogs/` only with Grep, never whole.
- **Builds and tests: fewer checks than edits** (the user, 2026-11-04). A small code edit gets
  NO build and NO test. Build (`run.ps1 -Steps setup`) only once a fair batch of edits has piled up
  or a task is done. A CSV/sheet change never gets a build of its own: it rides along with the
  next code build (one setup reads it). `setup` twice only when Editor code changed
  (`Scripts/Editor/`: SetupProject*, BalanceImporter) -- Unity's first pass compiles it but runs the old. Run tests once, after a substantial body of
  changes (a whole feature or several tasks), as one general run in the background -- not per edit,
  not per small task. Never: tests for models/colours/sizes/texts/UI layout/balance numbers
  (verify_sheet covers the sheet), photo tests, a re-run after a green, tests after a `git pull`,
  re-running a known flaky test. A new test only for a new game rule or a fixed bug, preferably as
  checks added to the feature's existing test; break-to-verify only for a bug's regression test, once.
- Save tokens: read files in parts (offset/limit, Grep with head_limit); verify by tests and data
  diffs rather than by looking at screenshots; send photos to the user instead of viewing them.
- The project is worked on from two devices: `git fetch` before starting; once per device,
  `git config core.safecrlf false`.
- The repo is PUBLIC: nothing secret in commits.
