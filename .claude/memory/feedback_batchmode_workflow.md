Everything Unity-side (scenes, prefabs, ScriptableObjects, UI) is generated by
`Assets/_Project/Scripts/Editor/SetupProject.cs`; an edit only takes effect after a batchmode run.
The full procedure, traps and timings are in the repo card `Design/features/build-and-test.md` —
read it before the first Unity run of a session.

**How to apply:**
- Run Unity ONLY via `Tools/research/run.ps1 -Steps setup,setup,editmode,playmode [-Filter X] [-Graphics]`
  (in the background; never poll). Since 2026-10-21 it prints a short report: exit codes, compile errors,
  counts, each failed test with its message and line. **Trust the report; open `RunLogs/*.log` only for
  something the report cannot say**, and then with Grep/limits, never whole (the setup log is ~760 KB).
- Prefer `-Filter` on the touched feature's tests while iterating; a full run before committing.
- Never kill a Unity process without checking its command line — the user's Editor may be open
  (`-useHub -hubIPC`), on this project or on another one.

**Why:** the user set this up as the build system long ago; and the logs were the biggest token sink
after the memory notes (asked 2026-10-21 to cut token use).
