# Схема сенсорного управления

Статус: согласована и **реализована** 2026-08-20.

Решения пользователя, из которых собрана схема:
1. Дороги и заборы строятся линией пальца, камера в этом режиме — двумя пальцами.
2. Поворота камеры нет, угол фиксирован.
3. Короткий тап = выбор объектов и персонажей.
4. Отмена выбора жителя обязана существовать на телефоне (сегодня её нет вообще).
5. Снос — кнопка «Снести здание» в карточке здания, а не контекстное меню.
   Из-за этого долгий тап по зданию остался без содержания и оставлен свободным.
6. Солдаты выбираются **только** группами в панели армии. Тап по солдату в мире не делает ничего.
7. Дорога рисуется свободной траекторией, забор — прямым отрезком с автоснапом на ось
   (см. 4.5): забор почти всегда периметр, а снести кривую секцию по одной будет нечем.

---

## 1. Три правила, из которых выводится всё остальное

**П1. Одиночный драг принадлежит камере.** Единственное исключение — режим рисования дорог/заборов,
где драг рисует, а камера уходит на два пальца. Из этого правила автоматически исчезают все
случайные приказы и все случайно открытые карточки.

**П2. Тап срабатывает на отпускании, долгий тап — по таймеру.** Ни одно действие не выполняется
в кадре касания. Это то, что сейчас нарушено везде (`pointer.press.wasPressedThisFrame`).

**П3. Палец, начавший жест на UI, не трогает мир до конца касания — и наоборот.** Проверка одна,
в роутере, а не четыре копии `IsPointerOverUI()` в четырёх скриптах.

## 2. Словарь жестов

Распознаёт один компонент — `TouchInputRouter`. Остальные системы получают уже готовое событие
и ничего не знают про `Pointer.current`.

| Жест | Условие распознавания | Момент срабатывания |
|---|---|---|
| **Tap** | 1 палец, смещение < TapSlop, длительность < TapMaxDuration, второго пальца не было | на отпускании |
| **LongPress** | 1 палец, смещение < TapSlop, удержание >= LongPressDelay | по таймеру, до отпускания |
| **Drag** | 1 палец, смещение >= TapSlop | непрерывно, начиная с превышения слопа |
| **Pinch** | 2 пальца | непрерывно |
| **3+ пальцев** | — | ведёт себя как Pinch по первым двум |

Правила отмены:
- Превышение TapSlop навсегда отменяет Tap и LongPress для этого касания — обратного пути нет.
- Появление второго пальца отменяет всё, что копилось на первом (Tap, LongPress, начатый Drag,
  начатую линию в режиме рисования), и переводит жест в Pinch.
- Снятие одного пальца из пинча **не** возобновляет одиночный драг: оставшийся палец игнорируется
  до полного отпускания. Это лечит нынешний рывок камеры при выходе из пинча.

### Пороги

| Константа | Значение | Обоснование |
|---|---|---|
| `TapSlop` | 8 dp = `8 * max(1, Screen.dpi/160)` px | системный touch slop Android; в **физических** единицах, а не в пикселях, иначе порог разный на разных телефонах |
| `TapMaxDuration` | 0,35 с | |
| `LongPressDelay` | 0,5 с | |
| `FlingDamping` | `exp(-6 * dt)`, стоп ниже 0,5 м/с | |
| Зум | мультипликативный: `distance *= prevPinch / curPinch`, clamp 8…220 м | линейный по пикселям (сегодня) ощущается медленным вдали и рывковым вблизи |

### Камера

- **Панорама:** на touch-down луч в плоскость земли, точка запоминается; каждый кадр камера
  двигается так, чтобы **эта же мировая точка оставалась под пальцем**. Скорость становится
  верной на любом зуме и любом DPI сама собой — константа `touchPanSpeed` исчезает.
- **Инерция:** есть в Browse / CitizenOrder / ArmyCommand. **Выключена** в Placement и Draw —
  там инерция уводила бы прицел после отпускания.
- **Пинч:** одновременно зум к центроиду двух пальцев и панорама за смещением центроида.
- **Поворота нет** (решение п.2).

## 3. Режимы

Ровно один активный режим. Приоритет сверху вниз:

| # | Режим | Когда активен |
|---|---|---|
| 0 | **Modal** | `ModalGate.IsBlocked` — мир не принимает ввод вообще |
| 1 | **Draw** | выбрано здание с `keepSelectedAfterPlacement` (дороги, заборы) |
| 2 | **Placement** | выбрано обычное здание |
| 3 | **ArmyCommand** | выбрана группа армии |
| 4 | **CitizenOrder** | выбран житель |
| 5 | **Browse** | по умолчанию |

## 4. Таблицы «жест × цель → исход»

### 4.1 Browse

| Жест | Цель | Исход |
|---|---|---|
| Drag | — | панорама + инерция |
| Pinch | — | зум к центроиду + панорама |
| Tap | здание | открыть карточку — там же Ремонт, Улучшение, рабочие и **Снести здание** (Лаборатория → панель исследований) |
| Tap | житель, свободен | **выбрать** → CitizenOrder |
| Tap | житель, занят | тост «Житель занят» (сегодня — молчание) |
| Tap | солдат | ничего — армия выбирается только группами в панели (решение п.6) |
| Tap | орк / портал | ничего (зарезервировано под инфо) |
| Tap | дерево / камень | ничего — ручная добыча возможна только выбранным жителем |
| Tap | земля | закрыть открытую карточку здания, если она открыта; иначе ничего |
| LongPress | любая | ничего — **свободен** (решение п.5) |
| Double tap | — | зарезервирован, не используется |

### 4.2 CitizenOrder (выбран житель)

Выбор переживает панорамирование и зум — это прямое следствие П1.

| Жест | Цель | Исход |
|---|---|---|
| Drag / Pinch | — | камера, **выбор сохраняется** |
| Tap | земля, достижимая | приказ идти, жёлтая рамка клетки + OK! |
| Tap | земля, недостижимая | красная рамка + NO!, **выбор сохраняется** |
| Tap | дерево / камень, свободный | приказ добывать вручную |
| Tap | дерево / камень, занятый или саженец | красная рамка + NO! |
| Tap | **тот же житель** | **снять выбор** → Browse ← закрывает п.4 |
| Tap | другой житель, свободен | переключить выбор на него |
| Tap | другой житель, занят | тост «Житель занят», выбор не меняется |
| Tap | здание | **снять выбор** и открыть карточку здания → Browse (приказ «идти к стене здания», который получается сегодня, бесполезен) |
| LongPress | любая | снять выбор → Browse |
| Кнопка ✕ на бейдже | — | снять выбор → Browse |

### 4.3 ArmyCommand (выбрана группа)

Единственный вход в режим — кнопка группы в панели армии. Тапом по солдату в мире группа
не выбирается (решение п.6).

| Жест | Цель | Исход |
|---|---|---|
| Drag / Pinch | — | камера, выбор сохраняется |
| Tap | орк / портал | приказ атаковать, красный маркер |
| Tap | земля, достижимая | приказ марша, жёлтый маркер |
| Tap | земля, недостижимая | ничего (сегодня — тоже ничего, но молча; добавить красный маркер) |
| Tap | здание | снять выбор и открыть карточку → Browse |
| Tap | иконка группы в панели | снять выбор (уже есть, `ArmyManager.ToggleSelection`) |
| LongPress | любая | снять выбор → Browse |
| Кнопка ✕ на бейдже | — | снять выбор → Browse |

### 4.4 Placement (обычное здание)

Призрак **прибит к точке прицела** — фиксированной точке экрана в центре верхних 55 % по
вертикали, чтобы не попадать под хотбар и не закрываться пальцем. Игрок двигает мир под призраком.

| Жест / элемент | Исход |
|---|---|
| Drag | панорама, **без инерции**; призрак остаётся в точке прицела, клетка пересчитывается каждый кадр |
| Pinch | зум + панорама, без инерции |
| Tap по земле | **перенести точку прицела** в точку тапа (грубое наведение), здание **не ставится** |
| Tap по призраку | то же, что кнопка ✓ (крупная удобная цель) |
| LongPress | ничего |
| Кнопка **✓** | поставить; погашена, когда нельзя |
| Кнопка **↻** | поворот на 90° (уже есть) |
| Кнопка **✕** | отменить → Browse; **скрыта**, пока не поставлена обязательная Ратуша |
| Строка причины | под кнопками, пока ✓ погашена: «Не хватает: дерево 20» / «Занято» / «Только на воде» / «Нужен: Дом» |

Строка причины заменяет нынешнюю схему, где невозможность видна только цветом призрака, а
«не хватает ресурсов» уходит строчкой в лог на 8 строк и там тонет.

### 4.5 Draw (дороги и заборы)

Единственный режим, где нарушено П1: одиночный драг рисует, камера — на двух пальцах.
Об этом сообщает подсказка при входе: «Ведите пальцем. Камера — двумя пальцами».

Жесты общие для обоих типов, различается только **форма линии** (см. ниже).

| Жест / элемент | Исход |
|---|---|
| Tap по земле | поставить одну клетку |
| Drag | **тянуть линию** за пальцем: превью, ничего не тратится |
| Drag → отпускание | поставить всю линию разом, списать ресурсы один раз |
| Drag → появился 2-й палец | линия **отменена целиком**, ничего не построено, жест становится камерой |
| Pinch | камера: зум + панорама, без инерции |
| LongPress | ничего |
| Кнопка **✕** | выйти из режима → Browse |

**Дорога — свободная траектория.** Все клетки, через которые прошёл палец. Дорога вьётся,
кривая линия здесь нормальный результат.

**Забор — прямой отрезок с автоснапом на ось** (решение п.7). От клетки касания до текущей
позиции пальца строится ПРЯМАЯ, привязанная к ближайшей из трёх осей: горизонталь, вертикаль,
45°. По мере ведения превью перещёлкивается между осями. Отпустил — секция встала; следующее
ведение начинается от нового угла, так прямоугольный периметр строится четырьмя движениями.
Причина: забор почти всегда периметр, а сносить кривую секцию будет нечем — снос работает
только целым зданием.

Правила линии (общие):
- Невалидная клетка в середине (занято, вода, вне карты) **пропускается**, линия не рвётся.
- Превью считает итог: «Дорога ×7 — 35 дерева». Если ресурсов хватает не на всю линию,
  клетки сверх бюджета показаны красным заранее и не строятся; строится префикс от начала линии.
- Повторный проход пальцем по уже включённой клетке ничего не меняет (идемпотентно).
- Отдельного прохода по заборам НЕ нужно (проверено при реализации): `FenceNetwork.Register`
  пересчитывает не только новую клетку, но и её соседей, поэтому каждая секция чинит форму
  предыдущей по мере роста линии.

## 5. Переходы между режимами

```
Browse ──tap по зданию в хотбаре──────────────► Placement / Draw
Browse ──tap по жителю (свободному)───────────► CitizenOrder
Browse ──кнопка группы в панели армии─────────► ArmyCommand

Placement ──✓ (обычное здание)────────────────► Browse
Placement ──✕─────────────────────────────────► Browse
Draw ──────✕─────────────────────────────────► Browse   (✓ нет: линия ставится отпусканием)

CitizenOrder ──tap по нему же / здание / longpress / ✕──► Browse
ArmyCommand  ──tap по зданию / longpress / ✕ / иконка───► Browse

Любой режим ──открылась модалка──► Modal ──закрылась──► тот же режим
```

Взаимоисключение режимов обеспечивает роутер, а не взаимные проверки скриптов друг о друге.

## 6. Элементы HUD, которых схема требует, а сейчас нет

| Элемент | Зачем |
|---|---|
| **Бейдж выбранного** (житель / группа) с кнопкой **✕** | единственный всегда доступный выход; прямо закрывает п.4 |
| **Кнопки ✓ / ↻ / ✕** в режиме Placement | ↻ уже есть; ✓ и ✕ новые |
| **Строка причины отказа** | заменяет молчащий красный призрак |
| **Точка прицела** (перекрестие + подсветка клетки) | без неё непонятно, куда встанет здание |
| **Кнопка «Снести здание»** в карточке + подтверждение | **сноса в игре нет вообще** — см. раздел 7 |
| **Превью и стоимость линии** в Draw | |
| **Тост «Житель занят»** | сегодня тап по занятому жителю молчит |

Размеры и безопасная зона:
- Кнопки категорий 80 px при reference 1080 по высоте ≈ 5 мм на плотном экране — вдвое меньше
  минимума для пальца. Поднять до ~110. Хотбар 130 нормальный.
- `Screen.safeArea` не учитывается нигде — на телефоне с вырезом и жестовой полосой часть UI
  недоступна. Нужен `SafeAreaFitter` на корневом RectTransform игрового Canvas.

## 7. Снос здания (новая механика)

Механики сноса в игре нет вообще — в коде нет ни одного упоминания. Схема её требует, потому
что без сноса любая ошибка размещения необратима, а забор, поставленный кривой линией, нечем
исправить. Вход — короткий тап по зданию → карточка → кнопка **«Снести здание»** (решение п.5).

Правила (значения — предложение, требуют подтверждения):

- **Кнопка внизу карточки, красная, визуально отделена** от Ремонта и Улучшения — соседство
  «улучшить / снести» на расстоянии пальца иначе будет стоить игроку зданий.
- **Подтверждение обязательно**, через существующий `ModalGate`: «Снести Лесопилку? Вернётся:
  дерево 10». Действие необратимо, а палец промахивается.
- **Ратушу снести нельзя** — её потеря есть поражение (`BuildingInstance.TryDamage` → GameOver).
  Кнопка на её карточке отсутствует.
- **Возврат ресурсов:** доля от всего вложенного (постройка + все улучшения). Новая колонка
  `demolish_refund_fraction` в economy-табе — по правилам проекта число живёт в таблице, не в C#.
  Предлагаемый дефолт 0,5.
- **Рабочие** освобождаются в idle, как при `LayOffWorkersBeyondWorkforce`.
- **Клетки** освобождаются `GridManager.SetAreaOccupied(..., false)`.
- **Дорога:** `RoadNetwork` сегодня умеет только `RegisterRoad` — понадобится `UnregisterRoad`.
- **Забор:** `FenceNetwork.Unregister` уже есть; после снятия пересчитать форму соседних секций.
- **Горящее здание:** снос гасит пожар (`FireManager`), а не оставляет висящий очаг.
- **Лог:** «Снесено: Лесопилка», как и для постройки.
- **Заметка по балансу:** при возврате 0,5 снос здания под ударом орков выгоднее его потери.
  Либо возврат ниже, либо снос запрещён, пока идёт рейд. Решить при балансировке.

## 8. Что из кода удаляется

- Edge-pan целиком: `EdgePan`, `EdgePush`, `edgePanZoneFraction`, `edgePanPixelsPerSecond`
  и их тесты. Это был обход того, что палец занят зданием; при прибитом призраке проблемы нет.
- Константа `touchPanSpeed` — панорама становится world-anchored.
- Четыре копии `IsPointerOverUI()` в `BuildingPlacer`, `BuildingSelector`, `CitizenSelector`,
  `ArmyOrderInput`.
- Взаимные проверки «уступи другому»: `buildingPlacer.IsSelecting` и
  `ArmyManager.SelectedGroup != null` в чужих `Update()`.
- Постановка здания в кадре нажатия (`TryPlace` под `pointer.press.wasPressedThisFrame`).

Клавиатура и мышь сохраняются как есть: WASD, колесо, ПКМ = отмена, Esc, R, цифры 1-9.
Роутер отдаёт им те же события Tap/LongPress, что и тачу.

## 9. Открытые вопросы

1. **Доля возврата при сносе** (`demolish_refund_fraction`) и запрет сноса во время рейда —
   см. заметку по балансу в разделе 7.
2. **Снос дороги и забора поштучно.** Схема даёт снос только целым зданием: одна клетка дороги
   и одна секция забора — тоже здания, так что технически они сносятся, но каждая через
   собственную карточку. Для длинной дороги это утомительно. Если понадобится, поверх схемы
   ляжет «режим сноса» — тот же Draw, но стирающий; сейчас в спецификации его нет.
3. **Долгий тап свободен** во всём режиме Browse. Если найдётся применение — место есть.
