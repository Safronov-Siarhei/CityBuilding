## The loop
1. Make sure the user's Editor isn't open on THIS project (their Editor on `D:\Fork\AC` doesn't block).
   Find the real Editor by command line (`-useHub -hubIPC`), never kill Unity blindly.
2. Edit .cs / CSV.
3. Run `Tools/research/run.ps1 -Steps setup,setup,editmode,playmode [-Filter X] [-Graphics]` in the
   background -- but only as CLAUDE.md's rule allows: no build or test for a small edit; build after
   a batch of edits; ONE general test run after a substantial body of changes (the user, 2026-11-04). (The older
   `rebuild_twice_and_test.ps1`, `retest_fresh.ps1`, `playmode_only.ps1` still work but print no report.)
4. **Read the script's REPORT, not the logs** (it STOPS after a step with compile errors): per step exit code + time, compile errors and exceptions
   (distinct, capped), test counts, and each failed test with 4 lines of message and its first
   `Assets/_Project/...cs:N`; a results file older than the step is called stale. Logs and XML live in
   `RunLogs/` (gitignored; setup log ~760 KB) — open one only for what the report can't say, with Grep.
5. Commit source + balance first, then the regenerated assets as their own commit; push right away.
   `git diff` shows generated Unity YAML under `Assets/_Project` as "Bin" (`.gitattributes` `-diff`);
   `git diff --text` if one really must be read.

Timings (warm): SetupProject ~70–100 s, a test pass 30–120 s; COLD (fresh Library, first graphics run)
15–20 min. Assemblies: `CityBuilder.Runtime`, `CityBuilder.Editor`, `CityBuilder.Tests.EditMode`,
`CityBuilder.Tests.PlayMode` (.asmdef). Pure formulas are public statics so EditMode can test them
without a scene. To prove a refactor of generated assets changed nothing, diff the YAML field by field
ignoring fileIDs, not by reading churn.

**Per-device git setting:** `git config core.safecrlf false` — silences the per-file "LF will be
replaced by CRLF" warnings (`core.autocrlf` is true and half the repo is LF). Set on 2026-10-21 on the
`D:\Fork` machine; run it once on any other device.

## Traps
- Call `run.ps1` from PowerShell itself (`& ./Tools/research/run.ps1 -Steps setup,setup,...`). Through
  `powershell -File` the comma list arrives as ONE step name, nothing runs, and it still prints
  `RUN FINISHED` with exit 0.
- The FIRST run after a .cs edit compiles new code but runs the OLD — run twice. An Editor-assembly edit
  (SetupProject, BalanceImporter) needs the SetupProject pass itself twice.
- A failed compile takes ~10 min to exit. Shell returns before Unity exits. `Start-Process -Wait` can
  wedge on helper processes — use `$p.WaitForExit()`.
- Every SetupProject run rewrites ~200 assets with new fileIDs (pure churn — commit it; never revert partially).
- Half the repo is CRLF, half LF — detect before patching. EditMode never calls `OnEnable`.
- Photos: PlayMode WITHOUT `-nographics` writes `playtest_shots/` (`PlaytestCapture`, `PlaytestWorld`);
  first graphics run re-imports shaders (~10 min). Scene loading helper `PlayModeScene`.
- Runtime shaders must be in Always Included (`IncludeRuntimeShadersInBuilds`, guarded by
  `AlwaysIncludedShaderTests`); `Editor/ShaderTextureImport.cs` sets shader texture import.
- Under `-nographics` the minimap RenderTexture logs an error — `LogAssert.ignoreFailingMessages` in setup.
- A test that never failed proves nothing — verify a green by breaking the code under it.
- Known flakes: `ForestClickTargetingTests` (unseeded forest), `Photograph_TheBuildingLevels`.

## Builds
**APK size vs Telegram's 50 MB** (2026-10-22: 60,3 MB → 46,4 MB): `BuildAndroid` builds with LZ4HC,
IL2CPP OptimizeSize, `stripUnusedMeshComponents`, Medium managed stripping (the game uses no
reflection -- keep it that way, or Medium strips what it reaches); `UiTextureImport` overrides the
interface pictures to ASTC 4x4 on Android only; `ModelImportDefaults` compresses maps at Low and set
pieces at Medium. Both importers carry `GetVersion()` -- bump it when their rules change, or nothing
already imported is redone. If the APK grows past 50 again, read the build log's "Uncompressed usage by
category" and the APK's own entries (`data.unity3d`, `libil2cpp.so`, `libunity.so`) before guessing.
`Tools/research/build_android.ps1 [-Development]` (`Editor/BuildAndroid.cs`) and `build_windows.ps1`
(`Editor/BuildWindows.cs`) → `D:\Builds CB` (previous build deleted first) → Telegram via
`send_build_to_telegram.py` (token from `TELEGRAM_BOT_TOKEN`; 50 MB cap). Identifier
`com.depigogames.citybuilding`. The repo is PUBLIC — nothing secret in it.
**This machine (2026-11-12): Unity 6000.5.4f1 with Android Build Support is in
`C:\Program Files\Unity\Hub\Editor\6000.5.4f1`** (build_android.ps1 finds it); a release APK takes ~4.5 min.
