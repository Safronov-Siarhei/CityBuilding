Since 2026-08-14, combat and economy balance is **data, not code**. Do not add or edit gameplay constants in the runtime scripts — the ones that were there are deleted.

The chain: Google Sheet (authoring) → `Assets/_Project/Balance/units.csv` + `economy.csv` (committed) → `BalanceImporter` (Editor) → `Assets/_Project/Resources/BalanceConfig.asset` → `BalanceConfig.Instance` at runtime.

- **To change a number:** edit the sheet (or the CSV directly), then *CityBuilder → Balance → Rebuild Config From CSV*, or just run the normal batchmode `SetupProject.Run`, which rebuilds the config first thing.
- **Verifying a paste landed: Google caches the published CSV.** On 2026-08-17 a plain download returned the pre-paste version twice in a row and made a completed paste look truncated at exactly 100 rows. Always append a cache-buster (`&nocache=$RANDOM`) and send `Cache-Control: no-cache` when diffing a tab against the repo, or you will chase a phantom. (A newly created tab genuinely does default to ~100 rows, which is what made the stale copy so believable.)
- **`CityBuilder → Balance → Pull From Google Sheets`** downloads the published-as-CSV tabs into the committed files. **Live since 2026-08-14**: the sheet is published and all five tab URLs are filled in `Assets/_Project/Balance/BalanceSheetSettings.asset` (doc id `1eroe1LMQCrpFtP4se7Oae4pGv-aOrHiqYAMdWKxxook`, tabs `units` gid 538856846 / `economy` gid 257341966; published-to-web links, no auth, no Google Cloud project). The build and tests never touch the network — that's why the CSVs are committed.
- A published tab exports **the prose under the table** as ordinary rows, and that text lands in column A — the id/key column. `BalanceImporter.IsNoteRow` skips rows whose cells after the first are all empty. Keep any new note in a single cell of column A only; a note spread across columns will be read as data.
- The committed CSVs now look like the sheet's real export: extra derived columns (`dps`, `ttk_*`, `coins_per_hp`) and quoted decimal commas. Both are handled (columns matched by name, comma parse fallback) — don't "clean them up" back to a hand-written shape.
- **Five tabs → five CSVs:** `units`, `economy`, `buildings`, `recipes` and `localization` (that last one is text, not balance — see [[project_localization]]). Everything tunable is data; nothing gameplay-numeric is left as a C# constant.
- **`recipes` (added 2026-08-17, `f0ebd2f`)** owns ALL production — one row per thing a building can make (`building`, `recipe_id`, `display_name`, `in1/in1_amount`…`in3`, `out`, `out_amount`). `produces`/`consumes` are gone from the buildings tab. A building with no recipe row produces nothing (deliberate for Пристань/Водяная мельница). **The split to remember:** a recipe says what one BATCH is; the buildings tab's `batches_per_tick` (renamed from `production_per_tick`, still per level) says how many batches a worker does. That is what keeps per-level upgrades working. `MaxRecipeInputs` in BalanceImporter is how many `in{n}` pairs are read.
- **`buildings` (added 2026-08-14, `193512c`)** holds all 49 buildings — cost per resource (`cost_wood`…`cost_gold`), population, production, health, defence, reveal radius, `requires`, and the full `up2_*`/`up3_*` upgrade costs. Only NUMBERS: footprint, height, colours, prefab generator/FBX and the road/water flags stay in `SetupProject.cs`, which now calls `CreateBuildingData("House", footprint, height, colours, style, materials)` and pulls the rest via `Balance(id)`/`ApplyBalance`. A missing row is a loud build error, not a silent default.
- The old hidden rules are now visible data: `ScaleCost(1.6x/2.8x)` and the six `.Add()` mutations that bolted iron/coal onto mines and the defence line are gone — the tab spells out all ten upgrade amounts (formulas in the sheet, hand-authored where the rule deliberately doesn't apply). Prerequisites come from the `requires` column via `ResolveBuildingRequirements`, run once after every asset exists.
- The multipliers live in `economy` as `building_upgrade_level{2,3}_multiplier` **for the sheet's formulas only** — no code reads them.
- **Storage capacity (added 2026-08-15, `45cb0ee`):** resources are no longer unbounded. Capacity is per FAMILY — `Materials` / `Food` / `Valuables` (`ResourceStorage.GroupOf`) — not per resource. A building declares `storage_group` and `storage_capacity` (the latter picks up `_2`/`_3` per level); base ceilings are the economy keys `base_capacity_{materials,food,valuables}`. Three storehouses exist with placeholder geometry: Warehouse, Barn, Treasury. `ResourceManager.Add` now RETURNS how much fit — callers that care report the waste.
- **Per-level stats (added 2026-08-15, `daf66d7`):** a building's strength is `BuildingLevelStats` × 3, not flat fields — those were deleted, so nothing can read a stat without naming a level. The sheet authors level 1 in the plain column and the rest in `<column>_2` / `<column>_3`; **an absent or empty higher-level cell repeats the level below**, so only the stats an upgrade actually changes get typed. Covered today: `max_health`, `defense`, `citizens_granted`, `max_workers`, `batches_per_tick`, `storage_capacity`, `happiness`.
  - **Adding one is THREE places, not one** (learned the hard way on 2026-08-18 adding `happiness`): the sheet column, a line in `BalanceImporter.ReadLevels` (lookup is by column name, no fixed order), **and** a line in `SetupProject.CopyLevels`, which copies the level stats out of the config into each building's own `BuildingData` asset field by field. Miss the third and the value reaches `BalanceConfig` — so every EditMode test that reads the config passes — while the building standing in the scene is still worth zero. Only a PlayMode test that PLACES one can see that.
- Values written as field initializers in `BalanceConfig.cs` are a **fallback only** (asset missing → loud error + playable game). Never tune there.
- Nothing reads the config per frame: units copy what they need into fields at `Awake`/`Initialize`. Keep it that way (mobile-first, see [[feedback_mobile_first_optimization]]).
- `BalanceConfigTests` guards spreadsheet-shaped breakage (emptied cell, renamed row, zero interval, fraction out of 0..1); `ArmyBalanceTests` asserts *relationships* read from the sheet, not hardcoded numbers.

**Why:** tuning meant hunting constants across ~130 scattered `const` declarations, and understanding what a number meant (does tax cover the army? does a militia beat an orc?) meant recomputing it by hand every time. The spreadsheet's derived columns answer that continuously.

**How to apply:** when asked to retune anything, change the CSV/sheet and rebuild — and when adding a NEW tunable, add it to the CSV + `BalanceConfig` rather than as a `const`. See [[project_game_design_backlog]] for the army slice these numbers belong to.
